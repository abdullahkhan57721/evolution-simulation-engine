# Textbook Scope Boundary

This textbook is intentionally deep, but finite.

## In scope

```text
software architecture concepts needed by this project
simulation execution semantics
general evolution abstractions
biological specialization
kernel public API/runtime/source reading
complexity and memory reasoning
performance measurement judgment
readability/maintainability/extensibility/testability
review and design practice
```

## Out of scope

```text
complete beginner Python course
complete algorithms/data-structures curriculum
catalog of all software design patterns
CPython internals course
CPU/cache/microarchitecture deep dive
full history of every project PR
line-by-line annotation of every source file
```

When an out-of-scope topic matters, explain only enough to understand the engine
and link to a more appropriate resource if one exists.

## Why the boundary matters

More content is not automatically more learning. Every new concept increases
navigation and maintenance cost. Prefer depth around the engine's real decisions
and transferable reasoning skills over encyclopedic coverage.
