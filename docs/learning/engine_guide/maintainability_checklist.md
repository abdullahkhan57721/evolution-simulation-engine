# Maintainability Checklist

```text
[ ] One clear owner for each rule?
[ ] No duplicated semantic paths?
[ ] Public contract as small as practical?
[ ] Dependencies explicit?
[ ] Focused tests localize failures?
[ ] Change radius understood?
[ ] Real policy variation isolated behind contracts?
[ ] No speculative factory/registry layers without need?
[ ] Optimizations do not multiply invariant paths?
[ ] Authoritative docs live in one clear source?
```

Maintainability is the cost and risk of future change, not simply today's line
count.
