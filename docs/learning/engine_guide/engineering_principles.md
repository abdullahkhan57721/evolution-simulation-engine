# Engineering Principles Reinforced by the Textbook

```text
Correctness before convenience.
Domain meaning stays in the domain that owns it.
Small contracts beat universal base types when only a capability is required.
Transactions make failure semantics explicit.
Randomness is state when reproducibility/rollback matter.
Conflict selection and state mutation are separate responsibilities.
Accepted-only stochastic work belongs after resolution when proposal existence does not depend on it.
Define scaling variables before Big-O.
Measure the correct layer before optimizing.
Prefer algorithm/data-structure/repeated-work improvements over opaque tricks.
Memory analysis includes lifetime, not only size.
Readability and maintainability are constraints on optimization.
Extensibility means real variation points, not maximum abstraction.
Focused tests are executable architecture.
Public contract changes deserve change-radius analysis.
Stop optimizing when the remaining value does not justify conceptual debt.
```
